# AI tool usage

Codex was used for both planning and implementation of this assessment. It generated the initial architecture and code from the approved specification, then iteratively inspected, tested, and revised the FastAPI backend, PDF/XLSX ingestion, Chroma/SQLite data layer, native Groq/Gemini tool routing, deterministic fallbacks, five server tools, Next.js interface, deployment configuration, tests, and documentation.

The applicant manually exercised the deployed product and reported real failures involving repeated responses, narrow action-intent routing, cross-account/aggregate routing, incomplete quota fallbacks, and irrelevant document retrieval. Codex reproduced those cases, traced them through the implementation and Render logs, and implemented regression fixes. The most consequential reviews focused on repository/tool-layer authorization, explicit viewer denial, confirmation ownership and idempotency, agreement-versus-policy precedence, deterministic cancellation and credit arithmetic, relevance-first hybrid retrieval, fresh-turn handling, and the Render memory failure caused by Chroma's default embedding model.

Codex also ran the automated backend suite, built the frontend, tested the live Render API and Vercel UI, inspected deployment revisions/logs, scanned the repository for exposed credentials, and committed and pushed the resulting changes. No generated answer was treated as proof by itself: behavior was checked against the supplied PDFs/workbook, executable tests, HTTP responses, and deployed tool events. Real API and deployment tokens were kept in environment variables and were not intentionally written to repository files.
