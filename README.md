# ParcelPilot AI Support

An internal support/operations copilot for the supplied assessment pack. It uses guarded structured lookups, scoped document retrieval, deterministic cancellation/service-credit evaluation, and a confirmation-gated mock escalation.

## Local setup

Requirements: Python 3.11+, Node 18+, and npm. Copy `.env.example` to `backend/.env` or export the variables in your shell. `GROQ_API_KEY` is optional for the local deterministic demo; when supplied, the provider adapter tries Groq with retry/backoff and falls back to Gemini after retryable errors. Never commit keys.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

In another terminal:

```powershell
cd frontend
npm install
$env:NEXT_PUBLIC_API_BASE_URL="http://localhost:8000"
npm run dev
```

Open http://localhost:3000 and choose `priya`, `arjun`, `manager`, or `viewer`. The source pack is read from `data/raw/` by default. To rebuild the SQLite/Chroma runtime after changing raw files, delete `backend/runtime/` and restart; or set `PARCELPILOT_DATA_DIR` to another directory containing the same seven files.

Hosted model-routing probes are capped by `MODEL_DAILY_LIMIT` (default 40 per process day) to protect free-tier quotas. If Groq/Gemini times out, rate-limits, or reaches the cap, the tested deterministic local planner continues answering from guarded tools. No provider can guarantee an unlimited free quota, but quota exhaustion does not take down the demo.

## Tests and checks

```powershell
cd backend
pytest -q
```

The tests cover cross-account denial in every tool path, confirmation gating/idempotency, actual-document precedence and deprecation, agreement overrides, unverified context, and multiple record IDs. The UI shows each invoked tool as a badge. Without API keys, the local planner still demonstrates a complete multi-step flow; keys enable hosted model integration.

## Deployment

### Render (backend)

1. Create a free Render account, choose New > Blueprint, and select this GitHub repository.
2. Render detects `backend/render.yaml`; approve the web service.
3. Set `GROQ_API_KEY`, optional `GEMINI_API_KEY`, and `FRONTEND_ORIGIN` to the eventual Vercel URL. `SESSION_SECRET` is generated by the blueprint.
4. Wait for `/healthz` to report `{ "status": "ok" }`; free instances may sleep and cold-start.

### Vercel (frontend)

1. Create a free Vercel account and import the same repository.
2. Set Root Directory to `frontend` and `NEXT_PUBLIC_API_BASE_URL` to the Render URL.
3. Deploy, then update Render's `FRONTEND_ORIGIN` with the Vercel URL and redeploy if needed.

No Hugging Face Spaces, paid database, or card-required service is used. Runtime Chroma/SQLite/action data is ephemeral on Render and is rebuilt from committed raw data after a cold start.

## Safety and limitations

Authorization is enforced in the repository and tool implementations, not by the prompt. Active customer agreements override general current rules only for their account; deprecated policy and ticket resolutions are excluded from current evidence. State-changing escalations are drafts until a second explicit confirmation call. The mock auth and action ledger are assessment-only and should be replaced with production identity and durable workflow services before real customer use.
